## Decisions

**D1 — Conservation outside the seed span, against the mixture baseline, scoped on the BASELINE side.** The promoted window's repair render replaces the window's mixture rows. Tokens outside the seed span's walls were already correct — the span is the only thing the promotion was asked to fix — so they form the conservation set: the repair render must carry those tokens. Scoping is baseline-side because the repair render's tokens carry NO per-token timestamps (stream rows use span walls — the live profile "SHALL NOT consume token timestamps"): a baseline row fully outside the seed span is conserved whole; a row straddling the span walls is partitioned proportionally by word count at the wall (the live replacement-scope precedent), its outside piece conserved. The replaced mixture rows are the only in-run baseline: verifying against the ear-truth fixture at runtime was considered and rejected (fixtures never read by code paths — hard rule).

**D2 — Per-badge resolved ordered alignment (panel-corrected; global alignment is quantitatively unsound).** The repair render is two whole-window stream rows in deterministic order; a global ordered alignment of their concatenation against the time-interleaved baseline scores ~0.5 even for a PERFECT separated repair (the best split point caps it), compressing the dynamic range until no bar separates good from mangled. The guard therefore aligns PER BADGE: baseline conservation pieces are grouped by their rendered badge; each group's ordered tokens are aligned (LCS on normalized tokens: lowercase, punctuation/whitespace stripped) against the stream whose vote evidence resolves to that badge. The ratio is RECALL — LCS length over the group's token count — so repair-side tokens outside every group (seed-span words, unscopable without timestamps) cost nothing; PRECISION is recorded alongside recall in the census. Recall-per-badge catches both failure classes: fluent substitution collapses the group's LCS, and a badge flip on conserved text lands the conserved tokens in the wrong alignment (both groups degrade). Legitimate within-badge re-partitioning costs at most a small ratio penalty — pinned by the red fixture (interleaved two-badge baseline vs stream serialization: per-badge ≈ 1.0 where global ≈ 0.5). Hard verbatim equality was considered and rejected: the user ACCEPTED a one-word loss in the validated render, so a blanket hard invariant would reject the attested-validated outcome (whether a hard INTERIOR invariant survives is exactly what the offline pass decides — D3).

**D3 — The bar is settled offline first, and the user ruling is mandatory wherever hard conservation fails (panel-hardened stop-point).** An env-gated probe computes, for the three kept window shapes (validated 32.69s, mangled 30.68s, 12s control), the per-badge scoped ratios on the two attested cases. BEFORE any number is recorded, the statistic is frozen: denominator(s), normalization, minimum-conservation-set handling. The probe additionally asserts a REPRODUCTION CRITERION: the re-derived validated render passes that window's fixture pins and the mangled-case render fails the same pins — a mismatch is a recorded stop, user rules. The stop-point then decides: (a) hard non-seed-interior conservation holds for the validated render (the accepted loss sits inside the seed span or edge band) → hard interior invariant (preferred, fewer dials); (b) hard conservation fails → the bar is USER-RULED as a class dial, with a mechanically pinned separation margin between validated and mangled ratios — an implementer-chosen midpoint that merely "separates" does NOT ship. The 12s control's expected verdict is pinned in the same ruling. Recording: the dated bar constant + evidence sha256s go in the change record; raw ratios + full alignments go to the evidence home; the word-loss disposition is recorded as an enum (`seed-span-interior` | `conservation-set`), never text. The bar is calibratable only under the ear-truth fixture gate's governance, hold-out entries excluded (the live calibration clause applies); the 1.5 record verifies the attested windows map to non-hold-out entries. Retuning trigger: any later ear-validated guard stand-down reopens the bar.

**D4 — Edge-band exemption only if evidence demands it.** Default: no exemption — the guard conserves all text outside the seed span, absorbed edge rows included (absorbing a row whole raises the guard's obligations by exactly that row's tokens; mangle it → stand down). If the offline pass shows window-edge decode noise legitimately dropping tokens in the validated render, a documented edge band enters with its value taken from that same evidence — never chosen to fit the mangled case. Mis-badged edge-row head words (the validated D7 shape contains them) get their treatment pinned from the same evidence: cross-stream rescue or recorded exclusion, stated, not improvised.

**D5 — Fail-closed wiring, census visibility, per-seed outcomes (panel-completed).** The guard runs between repair-render construction and row replacement. Guard violation, guard error, or a missing/empty baseline → the promotion stands down and the window renders byte-identical to the mixture render (the existing degrade contract). The PRODUCTION regeneration census is the owner of the promotion's verdict surface (distinct from the gate's census; both token-only): for EVERY seed fire it records an outcome — promotion applied, guard stand-down, window not built (over-cap, no donor, deduped), separation unavailable — with walls, verdict, ratio, per-badge token counts + sha256, and badge resolution, so a mis-tuned bar is visible and correctable, never silent. Verbatim text only under env gate / evidence home.

**D6 — Promotion rebuilt from recorded findings; existing protections extend to windows.** Sources: issue #6 + the archived retranscription record. Seed definition (panel-scoped): trigger-fired spans that REACHED separation (the duration-floor carve-out never separates), whose final synthesis outcome is the FULL mixture render (partially-synthesized spans have no pure mixture baseline), and whose separated streams' Whisper decode exceeds the pinned ceiling. The seed-decode set is exactly that population — pinned in the delta, so exposure is measured by the census before any production run. The fingerprint decode's text is never rendered. Priorities: the repair pipeline's seed order is load-bearing (dedupe-to-first); scramble seeds enter AFTER loop candidates, and `LoopRepairCandidate` gains a seed-kind discriminator so ONLY promoted windows route through the guard. The promotion is a third seed source in the post-duplicate-resolution repair fold (after `resolve_duplicate_clusters`, with stutter/loop). Protections: a window containing a surviving manually-labeled row SHALL NOT promote; a window overlapping a floors-synthesized span SHALL NOT promote (re-decoding attested-good stream rows is risk with no upside) — at the ~192s window this block fires before the guard even runs, which is correct defense-in-depth; the guard's mangle case is validated offline by the probe.

**D7 — Pin-scoped waivers in the ear gate, with verdict-check coverage (panel-completed).** The waiver vocabulary becomes: a failing waivable pin resolves KNOWN-LIMITATION iff its LABEL appears in a complete amendment record's covers; verdict-level (non-pin) failures resolve KNOWN-LIMITATION iff their failure-kind id appears in covers. `covers` entries thus resolve against the entry's waivable pin labels ∪ the gate's enumerated failure-kind ids — this is what keeps the two existing limitation records (whose entries carry only hard pins and waive entry-verdict failures) satisfiable without new user rulings: their existing scope is re-expressed as check-kind covers, mechanically derived from each record's documented reason. Hard pins SHALL NOT carry labels and SHALL NOT appear in any covers list — they fail the gate regardless of amendment records. NO wildcard. Waiver resolution is extracted into ONE pure router (red-tested) so all four call sites (kind-keyed render failures, the two entry-verdict sites, the pin site) share it. The fixture-lint extends to BOTH gate fixtures: every record needs date + reason + non-empty covers whose entries resolve. The local fixture (evidence home) gains labels/covers derived mechanically from the existing records' documented reasons — a same-session local edit carrying the user's existing rulings; new pins added later are uncovered by default, forcing a fresh ruling (the intended behavior).

**D8 — Resumable census cache, keyed by window geometry (panel-corrected).** Seed detection decodes the seed-decode set meeting-wide (the dropped change's cold gate took 6.2h). The cache lives in the meeting folder — outside the repository (the meeting folder resolves under the OS Music dir), so gitignore/pathspec coverage is structurally moot; a red test verifies the resolved cache root is outside `git rev-parse --show-toplevel`. Key: window walls + absorbed-row id set + model versions (window shape derives from render rows and can shift on an engine change while span walls stay equal). Written atomically (temp + rename); an incomplete, corrupt, or key-changed entry re-decodes. Content: decode evidence only — never guard verdicts, never a text field (schema pinned).

**D9 — Hexagonal placement, pure router.** The guard, the seeding decision, and the waiver router are pure decisions over decoded evidence in the speaker run-assembly layer; the separation and transcriber ports are unchanged; no new adapters. The guard's red tests drive invented generic token arrays in plain `cargo test` (no audio, no models, no env gates) — existing `run_assembly.rs` test token style; captured real token sequences stay in the evidence home. Census I/O stays in commands. The fused build+splice in the repair fold factors into decide-then-splice so the guard slots in without duplicating assembly logic.

**D10 — Mechanical closure, shrunken ear round, pinned destinations.** The fixture pins already attest the validated window's render and the tail survival. The production verification is split: first a census-only pass (recorded seed-fire census — how many seeds fire, where — reviewed before any render changes), then the production run. Mechanical checks: the ~192s seed's window is BLOCKED (floors-region overlap) and/or stands down while the region's floors render keeps passing its pins; the validated window's render passes its pins; `transcript_sources` byte-identity; guard verdicts present in the production census — asserted by extending the existing replay/oracle harnesses, named in tasks. Clips are cut ONLY for attestation-unpinned promoted regions, and every clip/WAV/probe recording writes ONLY under the evidence home or the meeting folder — never a tracked path. If no new region promotes, the ear round closes mechanically with nothing new to hear.

**D11 — Vacuous apply accepted; universal guard rejected.** A promotion whose repair render is token-identical to the mixture render (the 12s shape) applies and is recorded: token-identical replacement still carries possible badge gains, and a no-benefit stand-down would be a new dial needing its own ruling. The guard deliberately routes ONLY promoted windows: applying the statistic to stutter/loop repair windows is zero new machinery but changes the behavior of ear-validated live repairs — recorded as rejected scope creep; the second-meeting objective can revisit it.

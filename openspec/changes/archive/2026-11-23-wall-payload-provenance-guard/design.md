## Context

Fork issue #7 (from `talkover-word-order-repair` probe-record addendum 5, 2026-11-21): the certified S16 window has three voices but the ConvTasNet separator produces two streams (`separation/conv_tasnet.rs` — fixed 2-source ONNX output), so the third speaker's clipped second talkover occurrence decoded as a one-word fiction under the wrong stream badge at the window tail. The first occurrence — the attested needle run — renders mid-row inside the user's stream row and is certified content.

This design was corrected by a five-reviewer adversarial panel (architecture, test coverage, security/PII, spec fidelity, applied science) before implementation; the load-bearing corrections are folded into the decisions below and marked [panel].

The repair machinery is landed and fail-closed: the attestation store entry is withdrawn, so no talkover-class rebuilt window ships today. But the legacy phrase-loop route has no attestation gate — `repairs_admissible_for_splice` admits `Legacy` seeds unconditionally, and phrase-loop repairs fire in production. A trim rule merged into the shared path would therefore ship deletions on live renders ungated. [panel] This is why enactment is census-gated (D8), not deferred-to-attestation.

Current mechanics that constrain the design:

- The splice chokepoint is `repair_overlap_rows_checked` (`run_assembly.rs:2288`) — every route funnels through `apply_loop_repairs` → this function. The production call sequence in `commands.rs` is: batch decode → `order_repairs_for_apply` → `repairs_admissible_for_splice` (computes `repair_render_sha256` + `attestation_verdict` inside) → `apply_loop_repairs`.
- Production synthesis ALWAYS carries utterances: `decode_stream_utterances` returns at least one `StreamUtterance` on every path, and `StreamEvidence.text` is set to the join of the utterance texts (`join_utterance_texts`). The splice renders per-utterance texts (falling back to `text` only when `utterances` is empty — a shape only test helpers produce); the hash reads `text`. [panel] A guard that trims only one of the two fields either ships bytes the hash doesn't pin or pins bytes the render doesn't ship.
- Synthesized rows carry `token_walls: None` (`synth_rows_for_streams`); the absorbed mixture rows carry real per-word walls (`token_walls: Some(Vec<TokenWord>)`, i64 absolute milliseconds, populated by `clean_source_walls` in `alignment.rs`) — this payload is the provenance oracle. It is a LOSSY oracle: the mixture whisper decode is itself what mangles talkovers, and at a successful separation's tail the mixture decode legitimately reports the other voice's word [panel].
- Wall semantics measured in code: `clean_source_walls` rejects mismatched word lists and manufactures 1ms seam slivers where rows are clipped; `walls_match_row` validates start-monotonicity but not non-overlap (a point can multi-cover); whisper token timestamps within a row can overlap.
- The offline probe and both harness suites call the splice directly — they do NOT drive the `commands.rs` sequence where a pre-verdict pre-pass would live [panel]; the guard function and the suites must be designed so the guard is actually exercised.

## Goals / Non-Goals

**Goals:**

- A measured, deterministic stand-down for synthesized tail tokens that positively contradict the absorbed mixture payload — trim semantics fully specified, tested red-first, and shipped in census (log-only) mode.
- Census evidence (counts-only) measuring the would-trim distribution on the reference meeting and a second meeting, and the firing-rate comparison of the candidate rules (bare-point vs interval-majority), BEFORE any trim reaches a render.
- The pinned attestation hash remains the hash of the render that actually ships, by construction: the guard edits utterance texts and re-derives `text`, and the hash is computed from the post-guard state.
- Mid-row synthesized content is structurally untouchable by the guard (needle protection).

**Non-Goals:**

- No 3-stream separation, no model export, no voice-count decision (issue #7 sketch 2).
- No trim enactment in this change: no store entry, no certification listen, no render change at merge. Enactment is the user-gated follow-up flip after the census review (D8).
- No new e2e smoke spec: the UI flow (transcript rows render whatever rows the pipeline persists) is unchanged; this change alters no rendered content at merge — the render-fidelity smoke corpus covers the surface (per AGENTS §3, recorded here as the deliverable decision).
- No change to mixture rows, gates outside the repair path, or the whisper/decode profile.

## Decisions

**D1 — Guard placement: pre-verdict, pre-hash, synthesis-level pre-pass.** The guard is a public function in `run_assembly` (its inputs — the walls idiom, `proportional_share`, `vetted_stream_pair`, `join_utterance_texts` — all live there), invoked in `commands.rs` between `order_repairs_for_apply` and `repairs_admissible_for_splice`, where the ordered syntheses, the aligned rows (absorbed payload), and `cluster_speaker` are all in scope. Signature shape: `(syntheses: &mut [SpanSynthesis], rows: &[AlignedSegment], cluster_speaker: &dyn Fn(u32) -> Option<String>) -> per-window trim/would-trim counts`. Rationale: `repair_render_sha256`'s contract is "the per-voice text the splice would render"; trimming inside the splice would ship trimmed rows under an untrimmed hash — the certify-bytes-vs-ship-bytes defect class the final S16 production run caught. Alternative rejected: splice-internal trim (hash re-architecting, no extra safety).

Hash truth holds under ONE invariant, pinned by test [panel]: after the guard, each stream's `text` SHALL equal `join_utterance_texts` of its pieces' texts, and the guard maintains this by editing the piece texts and re-deriving `text` in the same pass. `repair_render_sha256` is then computed from the post-guard state by the existing code, unchanged.

Vetting failure at guard time (badge resolution fails) = no-op for that window: the splice's own deterministic gates reject it downstream with the same reason. The double `CENSUS-STANDDOWN`-class log from guard-time and splice-time vetting is accepted (both token-only).

**D2 — Contradiction rule: interval-majority + width floor + frozen operator.** [panel — replaces the original any-hit bare-point rule, which over-fires for three measured reasons: the proportional wall of a LAST token tends to the piece end = window end, exactly where the mixture's own final word sits; seam clipping manufactures 1ms wall slivers; overlapping token timestamps multi-cover.]

- A token's derived interval `[wall_k, wall_{k+1})` comes from the same character-fraction placement (`proportional_share` idiom) applied to consecutive token boundaries; a token's proportional wall is its character-fraction position within its piece span (spec-level definition).
- TRIM requires ONE different-badge payload word that: (i) covers ≥ 50% of the token's derived interval (interval-majority); (ii) has wall width ≥ 50 ms (excludes manufactured slivers); (iii) normalizes differently under the frozen operator.
- Frozen comparison operator (the live spec's shape-check freeze): Unicode NFC → lowercase → strip non-alphanumeric → collapse whitespace → exact equality. Case-only, NFC-form-only, and punctuation-carrying differences STAY.
- Cover predicate: half-open `[start_ms, end_ms)` — a payload word ending exactly at a boundary does not cover past it (pinned by boundary fixture; the codebase already recorded the adjacent 1ms truncation lesson at span edges).
- Multi-cover precedence (payload words may overlap; multiple rows abut): max interval-overlap, then the donor row (largest window overlap, matching the splice's donor rule), then earliest start — pinned by fixture.
- Constants (50% / 50 ms) are census-dialed, never per-span: the census (D8) reports the would-fire distribution under this rule AND under the bare-point rule; the comparison is the rule-selection evidence.

**D3 — Tail-only scope and piece mechanics.** The guard walks each stream's pieces from the LAST token backwards, trimming while each token contradicts, stopping at the first kept token; mid-row tokens are never examined. A piece = a stream utterance when `utterances` is non-empty, else the single whole-span piece from `text` (the test-helper shape). An emptied piece is dropped and the walk CONTINUES into the previous piece; an emptied stream becomes `text: None` — never `Some("")` (the hash would otherwise read an empty text instead of the absent marker, and `join_utterance_texts` would re-admit an empty part). Excision is char-boundary-safe (whitespace-rejoin rewrites interior spacing; CJK decodes carry no internal whitespace). Tokens are whole-token trims: a single-token CJK piece therefore trims as a whole — behavior pinned by red test and surfaced by the census's contiguous-trim-length distribution, with no special case.

**D4 — Missing payload fails OPEN, per row.** Absorbed rows with `token_walls: None` contribute NO walls; rows that carry walls are still judged (the mixed Some/None shape — one validator-accepted row beside one proportional row — is routine, not degenerate). Rationale: the guard is an additive fiction stand-down, not an admission gate; the fail-closed layer for talkover windows is the hash/fingerprint verdict, untouched. A window whose every absorbed row lacks walls therefore no-ops (fail-open), exactly as the original D4 intended — now stated per-row.

**D5 — All routes, one implementation, census mode at merge.** The guard runs in the shared repair path for every route: legacy phrase-loop, attested-window, decode-tripped rebuild. Fiction is fiction regardless of route; a route-conditional guard would fork render semantics for no benefit. BUT [panel]: the legacy route has no attestation gate and fires in production today, so AT MERGE the guard runs in CENSUS MODE ONLY for every route — it computes and records what it would trim, and changes no render bytes. Trim enactment is D8's gate. This keeps the proposal's original "render-inert at merge" claim true for ALL routes, not just talkover ones.

**D6 — Evidence surfaces, token-only everywhere.** Two surfaces, both pre-defined (the panel found the original single-surface claim false: legacy windows never flow through `talkover_seed_census`, and the census formatter prints aggregates only):

- Talkover seeds: `TalkoverCensusInputs` gains a per-span trim count; a seed whose window's splice APPLIED with trims (or would-trims in census mode) records the token-only note `tail-trimmed:<n>` BESIDE its outcome token in the seed's census record — the outcome token itself remains one of the live enumeration (`fired+attested`, `awaiting-attestation`, …). Notes are recorded only for windows whose splice applied (joined against the applied-spans set), so a window that died downstream never claims a trim that never shipped. The census formatter is extended to print the note.
- Legacy windows: a token-only rejection-log-class line (`REPAIR-GUARD span=[a,b] trimmed=<n> | would_trim=<n>`), mechanical strings only.
- ALL guard log lines (`log::warn`/`debug`/`info`) are token-only: stream index, wall positions, counts. Never the trimmed token, never the covering mixture word, never any row text. [panel/security — repo precedent: committed gate-run logs archived into `openspec/changes/archive/`; a trim log would naturally name both words.]

**D7 — Certification re-binding (future, not this change).** Any future attestation of a guard-affected window pins the post-guard hash; the withdrawn entry stays withdrawn. Because D1 makes the hash bind post-guard content, a pre-guard pin fails closed to mixture mechanically — no migration step exists or is needed.

**D8 — Census-first enactment gate.** [panel/applied — the original "inert until attestation" framing was false for the legacy route.] The offline census is an env-gated, read-only, counts-only run (precedent: `MEETIFY_ALIGN_DEBUG`) over every repair-window shape, logging per window per stream: would-trim count and contiguous-trim-length distribution; trimmed-token punctuation/terminal-fragment breakout; token-interval coverage-fraction buckets; covering-word width buckets; piece-length bucket; route class; and — computed in-process, never persisted — the delta between the stream token's real decode walls and the covering mixture word's walls (the own-stream-evidence confound: a cross-badge difference at a tail is also what successful separation looks like, so trims are only justified where the stream's own decode had no real-wall support). Corpus: the reference meeting first; a SECOND meeting (the user names it) before enactment. Acceptance bar for enactment on a route: (i) would-trims occur only at tails; (ii) predominantly single-token contiguous; (iii) zero events inside certified-content regions; (iv) the placement census bounds last-token proportional-wall error against real walls below the covering-word width scale. Trim enactment on any route = a small follow-up flip, unlocked only by the user's dated review of the census note — the live "Candidate census precedes render changes" pattern.

## Risks / Trade-offs

- [The mixture payload is a lossy oracle, and cross-badge tail differences are the expected signature of successful separation] → the interval-majority + width-floor rule fires only on positive contradiction above a floor; the census's own-stream real-wall-delta field (D8 field f) measures the deletion-side risk directly, and enactment is barred until that field shows trimmed tokens sit where the stream's own decode had no wall support. A mixture hallucination at a tail can still launder itself into a veto — this is the residual risk the second-meeting census and the user's review own.
- [A trim can delete a genuine simultaneous-voice word — itself a hallucination-class defect under the user's metric] → deletion-side costs are counted in the census as their own class (punctuation/terminal-fragment and contiguous-length breakouts); census mode at merge means zero deletion risk until the bar clears.
- [Proportional placement error is systematically biased at the tail — the guard's only point of action] → measured, not assumed: the census reports the empirical error distribution of proportional-vs-real walls for last tokens against persisted wall payloads; if last-token error exceeds the covering-word width scale, the bare-point rule is disqualified outright (interval-majority is already the shipped rule).
- [Determinism] → trim inputs are the synthesis text/pieces and the once-decoded payload; Vecs-only discipline; pinned boundary, multi-cover, convergence, and two-run-hash fixtures. Unicode normalization is stable within a binary; a toolchain upgrade flipping a rare codepoint's fold would move hashes → fail-closed stale-attestation (safe direction), noted in the change record. **Build note:** strict idempotence is unachievable without deepening — the carved span is fixed while the text shrinks, so the surviving tail token's derived interval inflates westward and a re-invocation evaluates fresh walls; the rule stays single-pass conservative (re-judging a keep is the deletion-side risk this design bars), re-invocation converges within a bounded cascade — each trim strictly inflates the next surviving interval westward, so the trim set shrinks every pass; the fixture pins the third invocation at zero (a review-round-1 correction: the second invocation may deepen once) — and production is single-invocation (source-scan pin).
- [Order of gates] → decode-time trips run before the builder path; `vetted_stream_pair` re-runs stutter/punctuation/rate gates on the POST-guard text at splice. A tail-only trim can only shorten text and lower rates, so it cannot create a repeat or lift a rate over a ceiling; the guard's call-site is pinned structurally (source-scan test) so no future refactor can invoke it from the chunk path or the mass overlap pre-pass.

## Migration Plan

No data migration. The guard merges in census mode: no render changes anywhere, no store changes. Rollback = revert the commit (one pre-pass function + its wiring + census logging). Enactment is a separate, later, user-gated flip with its own dated census note.

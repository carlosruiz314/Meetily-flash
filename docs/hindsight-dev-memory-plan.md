## Architecture Summary

The bank remembers the **building** of Meetily-flash, not its meeting content. Per-session document upserts eliminate duplicate facts at the source; per-prompt recall stops injecting operational noise; three auto-refreshing mental models give every session a synthesized *current state*, *standing rules*, and *gotchas* view instead of dated fact fragments. All changes land in the existing hook plugin (`~/.zcode/hooks/hindsight/`) and its config (`~/.hindsight/zcode.json`) — the Meetily-flash repo itself is untouched except for this plan document.

## Retain Strategy

**Problem (verified):** `retain.py:146` mints `document_id = f"{session_id}-{timestamp_ms}"` per retained turn. Hindsight upserts only on *identical* document IDs (`retain.md:184`: an existing document with the same ID "and all its associated memories are deleted before the new content is processed"), so every 10th-turn full-window retain under a fresh ID re-extracts the same facts into new memories, forever. This is the direct cause of the stale blockers and near-duplicates surfacing at recall.

**Fix:** stable `document_id = {session_id}` per session (the canonical conversation pattern). The Stop hook accumulates each turn into a per-session state file and, on every Nth turn (unchanged: N=10), posts the **accumulated transcript** under the stable ID — Hindsight replaces the previous version and re-extracts from the latest full state. Within-session restatements update instead of duplicate. Cross-session staleness is handled by the mental models, not by retain.

**Mechanism:**

1. `retain.py` — after assembling `messages_to_retain`, append the turn to `session_turns_{session_id}.json` in state (new helper in `lib/state.py`), then post the accumulated transcript instead of the single turn:

```python
# lib/state.py — new helpers
import json, time
from pathlib import Path

STATE_DIR = Path(__file__).resolve().parents[3] / "state"  # match existing state layout
MAX_SESSION_CHARS = 200_000

def append_session_turn(session_id: str, user_text: str, assistant_text: str) -> str:
    """Append a turn to the per-session accumulation file; return the transcript."""
    path = STATE_DIR / f"session_turns_{session_id}.json"
    try:
        turns = json.loads(path.read_text(encoding="utf-8")) if path.exists() else []
    except (OSError, ValueError):
        turns = []
    turns.append({"user": user_text, "assistant": assistant_text, "ts": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime())})
    path.write_text(json.dumps(turns), encoding="utf-8")
    # Cap: drop oldest turns until under budget so marathon sessions can't balloon state
    out, total = [], 0
    for t in reversed(turns):
        size = len(t["user"]) + len(t["assistant"])
        if total + size > MAX_SESSION_CHARS and out:
            break
        out.append(t); total += size
    out.reverse()
    path.write_text(json.dumps(out), encoding="utf-8")
    return "\n\n".join(f"user: {t['user']}\nassistant: {t['assistant']}" for t in out)

def clear_session_turns(session_id: str) -> None:
    (STATE_DIR / f"session_turns_{session_id}.json").unlink(missing_ok=True)
```

```python
# retain.py — replaces the current per-turn retain call
transcript = append_session_turn(session_id, prompt, assistant_text)
if not transcript:
    return  # empty after formatting, skip

document_id = session_id  # STABLE: same-session retains upsert, never duplicate
response = client.retain(
    bank_id=bank_id,
    content=transcript,
    document_id=document_id,
    context=config.get("retainContext", "zcode"),
    metadata=metadata,
    tags=tags,
    timeout=15,
)
```

Notes:

Keep the role formatting/tag stripping from `prepare_retention_transcript` by passing the assembled turns through it first if it also strips memory tags; otherwise apply its sanitizer to the accumulated text.
- Do **not** clear the accumulation file on success: the next gated retain must re-post the full session so the upsert carries everything. Clear only when a session is known finished (safe place: a new `session_start.py` noticing a `session_turns_` file whose session id differs from the current one — optional housekeeping).
- Old per-turn documents stay untouched — history is preserved; the observation layer consolidates them going forward (see optional cleanup below).

## Recall Strategy

Per-prompt recall keeps its current shape (query = user prompt truncated to 800 chars, `budget: mid`). Two config changes in `~/.hindsight/zcode.json`:

```json
{
  "recallTypes": ["world", "observation"],
  "recallMaxTokens": 2048
}
```

- Dropping `experience` removes the "Assistant ran Grep search…" operational-narration memories from injection; they stay recallable on demand (`recall.md:91`: `types` filters which categories are *searched*; `world` = objective facts, `experience` = conversational events, `observation` = consolidated knowledge).
- 2048 tokens doubles the room for the facts that remain. `budget` stays `mid` — raising it increases daemon-side search depth/latency for marginal gain at this bank size.

## Mental Models

Three models, all whole-bank (`tags: []`), all auto-refresh, all created with **deterministic IDs** so retrieval is a direct GET — no ID storage, no list-and-match:

| ID | Name | Source query | Learns |
|----|------|--------------|--------|
| `current-state` | Current in-flight work | "What is the current state of in-flight work in this project: active OpenSpec changes, tasks blocked and who they are waiting on, decisions made recently, and the agreed next steps?" | A synthesized *now*, refreshed after every consolidation — replaces stale fact fragments |
| `standing-rules` | Standing rules and constraints | "What standing rules, workflow constraints, and directives has the user stated for working in this repo (git and commit rules, testing requirements, communication style, review processes)?" | Un-spoken directives (e.g. "nothing pushed to remote") that live in no repo file. AGENTS.md stays authoritative for repo rules |
| `gotchas` | Recurring gotchas and quirks | "What recurring technical gotchas, environment quirks, tooling traps, and debugging findings keep appearing across sessions in this project?" | The webpack-mock-seam / WASAPI-loopback class of knowledge, without re-deriving it per session |

All three use `trigger: {"refresh_after_consolidation": true, "mode": "delta"}` — delta refresh preserves unchanged sections byte-for-byte and surgically removes stale content (verified against the daemon's trigger schema), keeping `current-state` cheap to refresh and stable to read. `max_tokens` stays at the 2048 default. Creation is a reflect operation on first creation — expect the first synthesis of each model to take a minute of daemon time.

**Creation (idempotent ensure, new `lib/mental_models.py`):**

```python
# lib/client.py — new methods (endpoints verified against the live daemon OpenAPI)
def list_mental_models(self, bank_id, timeout=10):
    return self._request("GET", f"/v1/default/banks/{urllib.parse.quote(bank_id, safe='')}/mental-models", timeout=timeout)

def get_mental_model(self, bank_id, mental_model_id, timeout=10):
    try:
        return self._request("GET", f"/v1/default/banks/{urllib.parse.quote(bank_id, safe='')}/mental-models/{urllib.parse.quote(mental_model_id, safe='')}", timeout=timeout)
    except RuntimeError as e:
        if "HTTP 404" in str(e):
            return None
        raise

def create_mental_model(self, bank_id, mental_model_id, name, source_query, trigger, timeout=60):
    path = f"/v1/default/banks/{urllib.parse.quote(bank_id, safe='')}/mental-models"
    body = {"id": mental_model_id, "name": name, "source_query": source_query,
            "tags": [], "trigger": trigger}
    return self._request("POST", path, body, timeout=timeout)
```

```python
# lib/mental_models.py — ensure helper
MENTAL_MODELS = {
    "current-state": ("Current in-flight work",
        "What is the current state of in-flight work in this project: active OpenSpec changes, "
        "tasks blocked and who they are waiting on, decisions made recently, and the agreed next steps?"),
    "standing-rules": ("Standing rules and constraints",
        "What standing rules, workflow constraints, and directives has the user stated for working in this repo "
        "(git and commit rules, testing requirements, communication style, review processes)?"),
    "gotchas": ("Recurring gotchas and quirks",
        "What recurring technical gotchas, environment quirks, tooling traps, and debugging findings keep "
        "appearing across sessions in this project?"),
}
TRIGGER = {"refresh_after_consolidation": True, "mode": "delta"}

def ensure_mental_models(client, bank_id, debug_fn=print):
    for mm_id, (name, source_query) in MENTAL_MODELS.items():
        existing = client.get_mental_model(bank_id, mm_id)
        if existing:
            continue
        debug_fn(f"Creating mental model '{mm_id}'")
        try:
            client.create_mental_model(bank_id, mm_id, name, source_query, TRIGGER)
        except Exception as e:
            debug_fn(f"Create failed for '{mm_id}': {e}")
```

**Injection (`session_start.py`):** after the existing health check, ensure the models exist, fetch each by ID (fast key-value lookup — not a search), and emit the contents with content in fresh chunks:

```python
# session_start.py — after server-reachable check
ensure_mental_models(client, bank_id, debug_fn=_dbg)
sections = []
for mm_id in MENTAL_MODELS:
    model = client.get_mental_model(bank_id, mm_id)
    if model and (model.get("content") or "").strip():
        sections.append(f"### {model.get('name', mm_id)}\n{model['content'].strip()}")
if sections:
    context_message = ("<hindsight_models>\n"
                       "Synthesized state from memory — hints only; repo records (AGENTS.md, specs, ledger) "
                       "are authoritative on any conflict.\n\n" + "\n\n".join(sections) + "\n</hindsight_models>")
    json.dump({"hookSpecificOutput": {"hookEventName": "SessionStart",
                                      "additionalContext": context_message}}, sys.stdout)
```

Models with empty `content` (created but never refreshed — e.g. bank was empty) are skipped silently; they populate after the first consolidation cycle.

## Compliance & Privacy Notes

- **Bank never reaches GitHub — structural guarantee:** the bank lives in the daemon's database under `~/.hindsight/`, outside every repository. The plan adds no code path that writes bank content into any repo. The one real risk is *manual* cleanup work: any export/dump produced while pruning legacy documents must be written under `~/.hindsight/` (e.g. alongside the existing audit logs), never into `Meetily-flash/`.
- **Hook config carries no bank content:** `zcode.json` changes are two key-value pairs; nothing PII-bearing enters the repo through configuration.
- **Existing PII stays local:** dev memories contain colleague first names and meeting context. Per your constraint (no PII on GitHub, local disk is fine), no scrubbing is required; do not enable any future cloud sync/telemetry on the daemon.
- Debug logs (`debug_log`) and state files write only under `~/.zcode/hooks/hindsight/` state directories — verify no new logging path is added that points into a repository.

These are architectural recommendations, not legal advice.
